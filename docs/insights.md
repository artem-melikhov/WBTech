# Инсайты

## Структура данных
- Train: 4.63М строк, 1000 маршрутов × 4630 временных меток (идеальная сетка)
- Период train: 2025-07-28 → 2025-11-01 10:30 (96.5 дней), гранулярность 30 мин
- Test: 8000 строк = 1000 маршрутов × 8 временных меток (2025-11-01 11:00 → 14:30)
- Зазор между train и test: ровно 30 мин (train заканчивается 10:30, test начинается 11:00)
- Тестовый день: суббота (dow=5)
- Пропусков нет, все значения целые, target — неотрицательное целое
- В test НЕТ status-колонок — только id, route_id, timestamp

## Характеристики целевой переменной
- Среднее: 261К, медиана: 236К, стд: 169К
- Нули: 1.5% (69841 строк) — редки, но присутствуют
- Асимметрия: 2.28 (правый скос, тяжёлый хвост до 10.8М)
- Высокая изменчивость: CV внутри группы (маршрут, день недели, получас) = 0.49 — данные шумные по природе

## Разброс по маршрутам
- Огромный разброс масштабов: min среднее=50К, max среднее=981К, CV=0.41
- Маршрут 702 — среднее 981К, маршрут 522 — 50К (разница в 20 раз)
- Все 1000 маршрутов из теста присутствуют в train

## Временные паттерны
- Очень слабая часовая сезонность (диапазон 229К–279К, ~20% разброс)
- Очень слабый недельный паттерн (Пн 252К → Чт 268К, <7% разброс)
- Автокорреляция таргета: lag 1 (30 мин) = 0.42, затем резко падает до отрицательных/нулевых значений
- Lag 48 (24ч) = 0.17, lag 336 (1 неделя) = 0.13 — слабая суточная/недельная периодичность

## Status-фичи
- status_1,2,3 (текущий склад): малые значения (среднее ~22), коррелируют с таргетом (0.45–0.51)
- status_4,5 (предыдущий склад): большие значения (среднее 119К, 702К), коррелируют с таргетом (0.37–0.43)
- status_6: низкая корреляция с таргетом (0.10)
- status_4 и status_5 сильно коррелируют между собой (0.88)
- Status-фичи НЕДОСТУПНЫ в тесте — нельзя использовать их напрямую для прогноза!

## Конвейерная природа status_1,2,3 (подтверждено эмпирически)
- status_1 → status_2 → status_3 → target_1h — это последовательный конвейер с временными лагами
- Лаг между этапами 1→2: 30–60 мин (у 55% маршрутов — 30 мин, у 41% — 60 мин)
- Лаг между этапами 2→3: 30–60 мин (у 69% маршрутов — 30 мин, у 28% — 60 мин)
- Лаг от этапа 3 до отгрузки: ровно 30 мин на 100% маршрутов — status_3 это непосредственная подготовка к погрузке
- Суммарный лаг s1→target: стабильно ~2 часа на всех маршрутах
- ВЫВОД: status_3 из последней строки train (10:30) напрямую предсказывает target первой тестовой точки (11:00)
- ВЫВОД: для фичей использовать status_3(t-1) как лаговый признак — самый ценный из всех status

- Среднее по маршруту+час: WAPE+RBias = 0.401 (хуже! час добавляет шум при малом кол-ве данных)
- Среднее по маршруту+день+час: WAPE+RBias = 0.409 (ещё хуже — переобучение на редких группах)

## Ключевой инсайт: status-фичи недоступны в тесте
Самые предсказательные признаки (status_1-6) отсутствуют в тестовой выборке. Это принципиально меняет подход к моделированию — модель должна либо:
1. Предсказывать БЕЗ status-фичей (использовать исторические паттерны, лаги, временные признаки)
2. Сначала предсказать status-фичи, затем использовать их для предсказания таргета
3. Использовать status-фичи только косвенно через лаговые значения таргета, в которых закодировано их влияние
